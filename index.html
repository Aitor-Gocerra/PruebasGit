📚 Manual de Referencia de Comandos Git

Guía completa de comandos Git organizados por categoría funcional

🎯 Introducción: Propósito y Estructura del Manual

Este documento es un manual de referencia técnica diseñado para ayudar a desarrolladores experimentados a localizar rápidamente comandos de Git según su propósito funcional. Su objetivo es servir como una guía de consulta ágil, eliminando la necesidad de navegar por documentación extensa para encontrar la herramienta adecuada para una tarea específica.

Estructura del Manual

La organización del manual sigue el ciclo de vida del desarrollo de software:

✓ Configuración Inicial
Configuración y creación de repositorios
✓ Trabajo Diario
Captura y gestión de cambios
✓ Gestión de Ramas
Desarrollo paralelo y fusiones
✓ Colaboración
Sincronización con equipos remotos
✓ Depuración
Análisis y diagnóstico de código
✓ Administración
Mantenimiento de repositorios

⚙️ Configuración e Inicialización de Proyectos

La configuración inicial y la creación de repositorios son el primer paso fundamental en cualquier proyecto gestionado con Git. Un entorno correctamente configurado es crucial para la estabilidad y eficiencia del flujo de trabajo.
git
El ejecutable principal del sistema Git; proporciona acceso a todo el conjunto de comandos.
git config
Gestiona y establece variables de configuración a nivel de sistema, global o local (repositorio).
git help
Muestra la documentación de ayuda para un comando específico de Git.
git bugreport
Recopila información del sistema y del entorno para facilitar la creación de informes de errores.
Credential helpers
Gestiona el almacenamiento seguro de credenciales (usuario/contraseña, tokens) para repositorios remotos.
git init
Crea un nuevo repositorio Git vacío en un directorio existente o en uno nuevo.
git clone
Crea una copia local de un repositorio remoto existente, incluyendo todo su historial de commits y ramas.

📝 Flujo de Trabajo Básico: Captura de Cambios

Este conjunto de comandos constituye el núcleo del flujo de trabajo diario en Git. Estos comandos operan principalmente entre el directorio de trabajo, el área de preparación (staging area) y el historial del repositorio.
git add
Añade los cambios de los archivos del directorio de trabajo al área de preparación para el próximo commit.
git status
Muestra el estado de los archivos en el directorio de trabajo y en el área de preparación.
git commit
Registra los cambios preparados (staged) como una nueva instantánea permanente en el historial del proyecto.
git notes
Permite añadir, eliminar o leer notas adjuntas a objetos de commit sin modificar el propio commit.
git restore
Restaura archivos del directorio de trabajo a un estado previo (desde el área de preparación o un commit).
git reset
Mueve el puntero HEAD a un commit especificado, con modos: --soft, --mixed, y --hard.
git rm
Elimina archivos tanto del directorio de trabajo como del área de preparación.
git mv
Mueve o renombra un archivo, directorio o enlace simbólico, actualizando el índice de Git.

Comandos Útiles Adicionales

git log --oneline

Muestra el historial de commits de forma compacta. Cada línea muestra:

  • Hash corto del commit (7 caracteres)
  • Mensaje del commit
  • Referencias como HEAD, ramas, tags
⚠️ git clean: El comando git clean elimina archivos no rastreados (untracked) del directorio de trabajo. ¡PRECAUCIÓN! Este comando elimina archivos permanentemente.

🌿 Gestión de Ramas y Fusiones

El modelo de ramificación de Git es un pilar fundamental que permite el desarrollo paralelo, la experimentación segura y la integración controlada de funcionalidades. Los comandos de esta categoría son cruciales para que los equipos trabajen en diferentes características de forma aislada.
git branch
Lista, crea o elimina ramas. Es el comando principal para la administración de las líneas de desarrollo.
git checkout
Comando de doble propósito para cambiar de rama y restaurar archivos. Ahora reemplazado por switch y restore.
git switch
Cambia a una rama especificada, facilitando la navegación entre líneas de desarrollo.
git merge
Fusiona el historial de una o más ramas en la rama actual. Es el método principal para integrar cambios.
git mergetool
Ejecuta herramientas de resolución de conflictos de fusión para ayudar a resolver diferencias complejas.
git stash
Almacena temporalmente los cambios no confirmados para cambiar de rama sin hacer un commit incompleto.
git tag
Crea, lista, elimina o verifica etiquetas firmadas con GPG, usadas para marcar puntos específicos en el historial (e.g., v1.0).
git worktree
Gestiona múltiples directorios de trabajo vinculados a un mismo repositorio, permitiendo trabajar en varias ramas simultáneamente.

🤝 Colaboración: Sincronización con Repositorios Remotos

La colaboración en equipos distribuidos es una de las fortalezas centrales de Git, y se fundamenta en la capacidad de sincronizar el trabajo entre diferentes repositorios. Los comandos de esta categoría son vitales para la interacción con servidores remotos.
git fetch
Descarga objetos y referencias de otro repositorio, pero no integra los cambios en la rama local.
git pull
Obtiene los cambios de un repositorio remoto y los fusiona (merge) o rebasea (rebase) en la rama local actual.
git push
Sube los commits locales a un repositorio remoto, actualizando las referencias remotas.
git remote
Gestiona el conjunto de repositorios remotos cuyo seguimiento se está realizando (añadir, eliminar, renombrar).
git submodule
Permite gestionar repositorios externos como subdirectorios dentro de otro repositorio, útil para dependencias de proyectos.

🔍 Inspección y Comparación del Historial

La capacidad de inspeccionar el historial, comparar versiones y analizar la evolución de un proyecto es fundamental para entender su desarrollo, depurar regresiones y revisar contribuciones.
git show
Muestra varios tipos de objetos de Git (commits, tags, árboles) de forma legible para el usuario.
git log
Muestra el historial de commits, comenzando desde el más reciente.
git diff
Muestra las diferencias entre commits, el área de preparación y el directorio de trabajo.
git difftool
Abre una herramienta de comparación gráfica para visualizar las diferencias mostradas por git diff.
git range-diff
Compara dos rangos de commits para identificar qué cambios son equivalentes y cuáles no.
git shortlog
Resume la salida de git log de una forma agrupada y concisa, ideal para notas de lanzamiento.
git describe
Genera una descripción legible y única para cualquier commit, basada en la etiqueta más cercana.

⚡ Manipulación Avanzada de Commits y Aplicación de Parches

Esta categoría agrupa herramientas avanzadas para la manipulación precisa del historial y la gestión de cambios en forma de parches. Aunque potentes, deben usarse con precaución, especialmente en ramas compartidas, ya que pueden reescribir el historial del proyecto.
git apply
Aplica un parche (patch) a los archivos y/o al área de preparación.
git cherry-pick
Aplica los cambios introducidos por commits existentes de otra rama en la rama actual.
git rebase
Re-aplica una serie de commits sobre una nueva base. Su modo interactivo (-i) es potente para reescribir el historial.
git revert
Crea un nuevo commit que revierte los cambios introducidos por uno o más commits anteriores.
⚠️ Advertencia: Los comandos de reescritura de historial como git rebase y git filter-branch pueden causar problemas en ramas compartidas. Úsalos solo en ramas locales.

🐛 Depuración y Diagnóstico de Código

Git no solo gestiona el historial de un proyecto, sino que también proporciona potentes utilidades para la depuración y el análisis de código. Estos comandos ayudan a identificar la introducción de errores en el historial, determinar la autoría de cada línea de código y realizar búsquedas de contenido.
git bisect
Realiza una búsqueda binaria en el historial de commits para encontrar rápidamente el commit que introdujo un error.
git blame
Muestra qué revisión y autor modificaron por última vez cada línea de un archivo.
git grep
Realiza una búsqueda de patrones de texto en los archivos rastreados por Git, opcionalmente a través de todo el historial.

🛠️ Administración y Mantenimiento del Repositorio

La administración de un repositorio es clave para mantener su eficiencia, integridad y limpieza a lo largo del tiempo, especialmente en proyectos de larga duración con muchos colaboradores.
git clean
Elimina archivos y directorios no rastreados del directorio de trabajo.
git gc
Ejecuta la recolección de basura (garbage collection), optimizando el repositorio y eliminando objetos innecesarios.
git fsck
Verifica la conectividad y validez de los objetos en la base de datos de Git.
git reflog
Gestiona el registro de referencias (reflog), que almacena el historial de las puntas de las ramas y de HEAD.
git filter-branch
Reescribe el historial. Se recomienda usar git-filter-repo como alternativa más segura y rápida.
git instaweb
Ejecuta instantáneamente un navegador web con una interfaz para el repositorio local.
git archive
Crea un archivo (e.g., zip, tar.gz) con el contenido de un árbol de commits específico.
git bundle
Empaqueta objetos y referencias en un archivo, útil para compartir repositorios sin conexión de red directa.

🔧 Herramientas Avanzadas y de Bajo Nivel (Plumbing)

Esta categoría final comprende el conjunto de herramientas de bajo nivel de Git, conocidas como "plumbing", que realizan las tareas fundamentales sobre las que se construyen los comandos de alto nivel. Aunque no son de uso diario para la mayoría de los desarrolladores, son fundamentales para la creación de scripts y automatización de flujos de trabajo.

Comandos de Bajo Nivel (Plumbing)

git cat-file
Proporciona el tipo y contenido de los objetos en la base de datos de Git.
git check-ignore
Depura los archivos .gitignore para ver por qué una ruta está siendo ignorada.
git checkout-index
Copia archivos desde el índice al directorio de trabajo.
git commit-tree
Crea un nuevo objeto de commit a partir de un objeto de árbol (tree) dado.
git count-objects
Cuenta el número de objetos desempaquetados y su consumo de disco.
git diff-index
Compara un árbol con el directorio de trabajo o el índice.
git for-each-ref
Itera sobre todas las referencias y ejecuta un comando para cada una.
git hash-object
Calcula el ID de un objeto y opcionalmente lo escribe en la base de datos.
git ls-files
Muestra información sobre los archivos en el índice y en el directorio de trabajo.
git ls-tree
Lista el contenido de un objeto de árbol.
git merge-base
Encuentra el mejor ancestro común entre dos commits para usarlo en una fusión.
git read-tree
Lee la información de un árbol en el índice.
git rev-list
Lista los objetos de commit en orden cronológico inverso.
git rev-parse
Analiza y estandariza los parámetros de revisión.
git show-ref
Lista las referencias en un repositorio local.
git symbolic-ref
Lee, modifica y elimina referencias simbólicas como HEAD.
git update-index
Registra el contenido de archivos en el índice.
git update-ref
Actualiza de forma segura el objeto al que apunta una referencia.
git verify-pack
Valida los archivos de empaquetado (.pack).
git write-tree
Crea un objeto de árbol a partir del contenido del índice actual.

Integración con Correo Electrónico

git am
Aplica una serie de parches desde un buzón de correo.
git imap-send
Sube una colección de parches desde una entrada estándar a una carpeta IMAP.
git format-patch
Prepara una serie de commits para ser enviados como parches por correo electrónico.
git send-email
Envía una colección de parches por correo electrónico.
git request-pull
Genera un resumen de los cambios para solicitar su inclusión en otro repositorio.

Sistemas Externos e Integración

git svn
Opera como un cliente de Subversion para interactuar con repositorios SVN.
git fast-import
Importa datos de forma masiva desde otro sistema de control de versiones a Git.

Administración de Servidor

git daemon
Ejecuta un servidor Git simple para repositorios públicos sin autenticación.
git update-server-info
Actualiza archivos auxiliares necesarios para servir un repositorio a través de protocolos "dumb".
ℹ️ Nota: Los comandos de bajo nivel son herramientas poderosas para la automatización y scripting, pero requieren un profundo entendimiento de la arquitectura interna de Git. Úsalos con cuidado.
